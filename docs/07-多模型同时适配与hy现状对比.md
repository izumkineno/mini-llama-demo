# 07-多模型同时适配：hy 现状与主流方案对比

> 搜集日期 2026-10-17。§1 现状依据本仓库源码（`src/` + `third_party/llama/include/llama.h` 实测）；
> §2–§4 外部方案依据各项目官方文档（链接见 §5，其中 Ollama Modelfile 与 llama.cpp server README 为本机抓取原文）。

## 1. 现状：本项目如何适配 hy（Hy-MT2-1.8B）

一句话：**单模型、编译时 pin**——Hy-MT2 的模板、哈希、采样链、tokenize flags 全写死在源码里，
换一个模型 = 改 N 处源码 + 重新编译。

### 1.1 写死点清单

| # | 写死项 | 位置 | 内容 |
|---|---|---|---|
| 1 | 模板版本 + 整体 sha256 pin | `src/prompt/embedded.h:25-29` | `kTemplateVersion="hy-mt2-v20261016"`，sha `a06006c7…f277d` |
| 2 | 模板本体（pre 47 B + post 20 B） | `src/prompt/embedded.h:36-42` + `static_assert`（47-49 行） | `pre=<｜hy_begin▁of▁sentence｜><｜hy_User｜>`，`post=<｜hy_Assistant｜>`（｜=U+FF5C，▁=U+2581） |
| 3 | 启动哈希自检 | `src/prompt/prompt_spec.cpp:26-42` `PromptManager::Init` | `sha256(pre+{{USER}}+post)` 必须等于 pin，否则 stderr + `exit 1`；**不碰文件系统** |
| 4 | 两段式 tokenize flags | `src/prompt/prompt_spec.cpp:67-80` `BuildPrompt` | `Tok(pre,T,T)` + `Tok("User input:\n"+用户文+方向后缀,F,F)` + `Tok(post,F,T)` 直接拼接 |
| 5 | 方向指令后缀（英文硬编码） | `src/prompt/prompt_spec.cpp:50-54` | `Translate the above … Output only the … translation…`（zh2en/en2zh 各一） |
| 6 | 采样链（顺序 + 参数锁死） | `src/prompt/prompt_spec.cpp:83-108` `CreateSamplerChain` | `penalties(64,1.10,0,0)` → `min_p(0.10,keep1)` → `temp(0.0)` → `greedy`；top-k/top-p/seed 不存在 |
| 7 | 引擎超参 | `src/core/engine.h:26-30` | `n_ctx=8192`，`n_batch=512`，`n_gpu_layers=99`，`kMaxPredictTokens=1024` |
| 8 | 单 GGUF 入口 | `src/main.cpp:24-28` | `lai-translate.exe <gguf>`，只收一个模型路径，无模型选择概念 |

设计取舍（有意为之，非疏漏）：`prompts/` 目录仅是取证存档（META/jinja/README/pin），
删改不影响 exe；运行时零文件依赖，防篡改靠编译时哈希。这是"单模型翻译机"的最简形态，
代价是**零扩展性**：Qwen/Mistral/Llama 等模板、特殊 token、推荐采样全与 Hy-MT2 不同，
逐一硬编码不可持续。

### 1.2 本仓库已具备、但尚未利用的多模型抓手

vendored `third_party/llama/include/llama.h` 实测存在（行号为当前版本）：

- `llama_model_chat_template(model, name)`（:655）——直接读 GGUF 内置 jinja 模板；
- `llama_model_meta_val_str / meta_count / meta_key_by_index / meta_val_str_by_index`（:630-642）——读任意 GGUF KV（含 `tokenizer.ggml.*`、`general.*`）；
- `enum llama_model_meta_key`（:282-295）——GGUF 可自带采样默认值（`SAMPLING_TOP_K/TOP_P/MIN_P/TEMP/PENALTY_*` 等）。

即：llama.cpp 侧的"自描述模型"基础设施已经就绪，瓶颈只在本项目的写死层。

## 2. 主流多模型适配方案（4 个）

### 方案 A：自描述 GGUF（读模型元数据 + 内置 chat template）

- **原理**：适配信息跟着模型文件走。GGUF KV 自带 `tokenizer.ggml.*`（词表/merges/BOS·EOS/add_bos/add_eos）、
  `tokenizer.chat_template`（jinja）、`general.architecture/name`，部分转换还写入采样推荐值；
  运行时经 §1.2 的 C API 读出，模板用 llama.cpp 内置 jinja 渲染（server 的 `--jinja` 即此路）。
  HuggingFace `transformers` 的 `apply_chat_template` 是同一思想的上游源头。
- **最小形态**：`Init` 后调 `llama_model_chat_template` 取模板 → 渲染 messages → 按 `add_bos/add_eos` 决定 flags；
  采样先读 `LLAMA_MODEL_META_KEY_SAMPLING_*`，缺项再回退编译时默认值。
- **出处**：llama.cpp `tools/server/README.md`（jinja 模板渲染章节）；GGUF 规范 `ggml/docs/gguf.md`（KV 命名表）；
  HF `docs/transformers/.../chat_templating`。

### 方案 B：模型包 sidecar（Ollama Modelfile / LM Studio 预设思想）

- **原理**：模型目录 = `模型.gguf` + 一个人类可读的适配文件（Ollama 叫 Modelfile，LM Studio 叫预设/preset）。
  Modelfile 的字段 chính是"多模型适配"的需求清单：`FROM`（基座/GGUF 路径）、`PARAMETER`
 （`num_ctx`/`temperature`/`top_k`/`top_p`/`min_p`/`repeat_last_n`/`repeat_penalty`/`seed`/`stop`/`num_predict`…）、
  `TEMPLATE`（Go 模板，变量 `.System/.Prompt/.Response`）、`SYSTEM`/`MESSAGE`/`LICENSE`。
  即 **TEMPLATE + PARAMETER + 元信息** 三件套，本项目 §1.1 的 8 个写死点恰好能逐一落进这三件套。
- **最小形态**（本项目口径）：`models/hy-mt2/adapter.yaml`，含 `template_pre/post`（或一段 jinja）、
  `tokenize_flags` 三段、`sampler_chain`（与 `CreateSamplerChain` 同构的声明式序列）、`stop`、`n_ctx` 上限、
  `sha256` pin（可选，延续现有防篡改语义）；`prompts/` 现有 META/jinja/pin 存档可直接升级为 sidecar v1。
- **出处**：`docs.ollama.com/modelfile`（本机抓取原文）；LM Studio 文档（预设 + OpenAI 兼容 server 章节）。

### 方案 C：OpenAI 兼容网关（server 进程承载多模型）

- **原理**：本进程退化为 HTTP 客户端，只发 `POST /v1/chat/completions`（body 带 `model` 字段）；
  多模型由 server 端承载：llama.cpp server、Ollama serve、LM Studio server、vLLM 全兼容该接口。
  llama.cpp server 更有原生 **router 模式**：不带模型启动即为路由器，经 `--models-dir`（GGUF 目录，支持单文件/多分片/mmproj 子目录约定）、
  `--models-preset`（`.ini`：`[preset]` 段逐模型覆盖命令行参数 + `[*]` 全局段 + `load-on-startup` 等路由专有键），
  按请求的 `model` 字段路由，`POST /models/load`、`/models/unload`、`GET /models`（`?reload=1` 刷新）管理生命周期，
  `/models/sse` 推下载/加载进度，未加载模型默认自动加载（`--no-models-autoload` 可禁）。
- **最小形态**：`lai-translate` 改为调 `http://127.0.0.1:9931/v1/chat/completions`；模型增删只动 server 的 `--models-dir`。
- **出处**：llama.cpp `tools/server/README.md`（"Using multiple models" 全章，本机抓取原文）。

### 方案 D：进程内多模型路由（router 模式的进程内版）

- **原理**：不引入外部进程，自己在 exe 内实现一个 `ModelRegistry`：`model_id → {gguf 路径, adapter（方案 B 的产物）, EngineRuntime 实例（lazy load）, LRU 卸载}`；
  请求按模型 id 路由，缺页加载 + 显存预算 + 空闲 sleep（llama.cpp server 的 `--sleep-idle-seconds` 是现成参照语义）。
- **最小形态**：CLI 增加 `--model <id>`（或 REPL 内 `/model <id>` 切换）；`EngineRuntime` 从单例改为按 id 持有的实例池，
  同一时刻只保留 N 个热模型，其余 `free` 掉 model 只留 adapter。
- **出处**：设计模式参照 llama.cpp server router（§2-C 出处）；无上游现成 C++ 库，需自研。

## 3. 对比

| 维度 | A 自描述 GGUF | B 模型包 sidecar | C 网关（OpenAI 兼容） | D 进程内路由 |
|---|---|---|---|---|
| 换模型是否重编 | 否（读文件头即可） | 否（增 sidecar 文件） | 否（server 端事） | 否（注册新 id） |
| 模板来源 | GGUF 内 `tokenizer.chat_template` | sidecar 内 pre/post 或 jinja | server 负责 | adapter（= B 的产物） |
| 采样来源 | GGUF 采样元数据（常缺项） | sidecar 声明（全） | server/请求参数 | adapter（= B 的产物） |
| 多模型并发/热切换 | 不解决（仍是单实例逻辑） | 不解决（只解耦描述） | **开箱即用**（router/load/unload/SSE） | 自研 LRU + lazy load |
| 部署形态 | 单 exe 不变 | 单 exe + 模型目录 | **双进程**（exe + server） | 单 exe 不变 |
| 延迟/资源 | 零额外开销 | 零额外开销 | +HTTP + 常驻 server 内存 | 按需加载，可 LRU |
| 工程量 | 小（读 API + 回退链） | 小～中（定 schema + 校验 + 版本管理） | 中（改客户端 + 部署 server） | 大（实例池 + 显存预算 + 并发串行化） |
| 与现状距离 | 近（只动模板/采样来源） | 近（`prompts/` 存档升级即可起步） | 远（架构翻转：直调 C API → HTTP 客户端） | 远（EngineRuntime 单例假设要重构） |
| 主要风险 | 转换质量参差：chat_template 缺失/错版常见，采样元数据覆盖不全，特殊 flags 仍需按架构特判 | schema 膨胀（每新增模型家族可能加字段）；校验不严则错配静默 | 端侧单机 exe 变双进程，零依赖优势丢失；server 升级/端口/鉴权成新运维面 | 多 model 并存的 VRAM 管理自己扛；decode 并发仍须串行化（现有 guardrail：同一 context 不并发） |

一句话选型：**单机翻译 exe、先解"换模型不重编" → B 为主、A 为辅（A+B 混合）**；
要多模型并发服务/给第三方提供接口 → 再谈 C；单进程多模型常驻且不接受双进程 → D。

## 4. 给本项目的分阶段建议

1. **近期（不动架构，B-lite）**：把 `embedded.h` 的单模板常量提升为**编译时注册表**
   `map<model_id, Adapter>`（hy-mt2 为首个条目，`kTemplateSha256` pin 语义逐条目保留）；
   CLI 加 `--model hy-mt2`（默认 hy-mt2 保持兼容）；`prompts/` 存档格式对齐 adapter schema。
   改动面：`PromptManager` 内嵌常量查表化 + `CreateSamplerChain` 参数化（参数来自条目，hy 条目值不变）。
2. **中期（B-full + A 回退）**：adapter 外置为随 GGUF 分发的 sidecar 文件，启动时校验 schema 版本 + sha pin；
   加载顺序：**sidecar 显式值 > GGUF 元数据（`llama_model_chat_template` + `SAMPLING_*`）> 编译时默认**。
   A 的价值在于"未知模型也能跑个 baseline"，B 保证"已知模型行为 pin 死可复现"。
3. **远期/按需**：需要同进程多模型常驻 → D（实例池 + LRU，复用 B 的 adapter）；需要对外提供服务/与生态工具互通 → C（llama.cpp server router 模式开箱即用，本项目届时只需写薄客户端）。
4. **现在不建议**：直接上 C——为单机翻译 exe 引入常驻 server 进程与 HTTP 链路，收益（多模型并发）当前用不上，成本（双进程部署 + 延迟 + 运维面）立即支付，得不偿失。
